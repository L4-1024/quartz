# 快速上手 18：手机和电脑怎么同步最省心？常见方案一次对比

![[mobile-sync.png|手机端同步方案封面]]

> 适读人群：需要在手机和桌面间同步笔记的读者
> 
> 阅读收获：根据平台与成本选择合适的移动端同步方案

## 概述

![[sync-options.png|手机端同步方案对比图]]

实现手机上查看/编辑 Vault 笔记，与桌面端保持同步。

---

## 方案对比

![[mobile-sync-decision-tree.png|手机端同步决策树]]

| 方案 | 平台 | 原理 | 优点 | 缺点 |
|------|------|------|------|------|
| Obsidian Sync（官方） | 全平台 | 端到端加密 | 体验最好，稳定 | 付费 $10/月 |
| Remotely Save | 全平台 | S3/WebDAV/OneDrive | 免费，灵活 | 需自备存储 |
| Syncthing (SyncThing) | Android + PC | P2P 同步 | 免费，不依赖云，全平台 | 配置复杂，需保持设备在线 |
| Working Copy (iOS) | iOS | Git 客户端 | 完整 Git 功能 | 需配合 Obsidian Mobile |
| Obsidian Git | 移动端 | Git | 桌面端方案 | 移动端支持有限 |

## 推荐方案：Remotely Save

### 安装

1. 在桌面端和移动端都安装 Remotely Save 插件
2. 插件市场搜索 "Remotely Save" 安装

### 配置

#### 方式一：S3 存储（推荐）

1. 注册 S3 服务（如阿里云 OSS、AWS S3）
2. 创建 Bucket
3. 获取 Access Key 和 Secret

4. 配置 Remotely Save：

```yaml
类型: S3
Endpoint: https://s3.amazonaws.com
Bucket: your-bucket-name
Region: us-east-1
Access Key ID: your-access-key
Secret Access Key: your-secret-key
```

#### 方式二：WebDAV

1. 自建 WebDAV 服务（如 Synology NAS、Nextcloud）
2. 或使用第三方 WebDAV 服务

3. 配置 Remotely Save：

```yaml
类型: WebDAV
URL: https://your-webdav-server.com/dav/
Username: your-username
Password: your-password
```

#### 方式三：OneDrive

```yaml
类型: OneDrive
Auth: 登录 Microsoft 账号
```

### 同步设置

| 配置项 | 建议值 |
|--------|--------|
| 自动同步间隔 | 5 分钟 |
| 同步方向 | 双向同步 |
| 冲突处理 | 保留两者 |
| Wi-Fi only | ✅（省流量） |

## 备选方案：SyncThing

### 核心问题：Fast Note Sync 的「被动同步」宿命

Fast Note Sync 本质上是一个基于 Obsidian 插件的同步工具，同步的发生必须依赖「Mac 端的 Obsidian 插件感知到了变化」。如果变化发生在没有 GUI、没有 Obsidian 界面运行的服务器上，Fast Note Sync 服务端无法工作。

**两个核心痛点**：

| 痛点 | 说明 |
|------|------|
| 同步全靠 AI「自觉」 | OpenClaw 在服务器上生成笔记后，需要调用推送脚本才会同步。如果 AI 模型不遵循，会漏同步 |
| 服务器成了「单向黑洞」 | 本地 Mac 往服务器推没问题，但反过来服务器改了，Mac 收不到 |

### 为什么选择 SyncThing

SyncThing 走的是**文件系统监控**的路线，在操作系统层面监控变化。

**核心优势**：

| 特性 | 说明 |
|------|------|
| 真正的双向同步 | 你在任何一端改了文件，另一端自动收到，不需要任何主动触发 |
| 声明式同步 | 监控的是文件系统的最终状态，只关心结果，不关心是谁写的 |
| AI 工作流解耦 | OpenClaw 写了一个文件 → SyncThing 检测到变化 → Mac 自动同步过来。全程没有「记得调用」这个环节 |

**SyncThing vs Fast Note Sync**：

| 对比 | Fast Note Sync | SyncThing |
|------|----------------|-----------|
| 同步触发 | 命令式（需主动调用） | 声明式（文件系统变化自动触发） |
| 服务器监控 | ❌ 无法监控 | ✅ 操作系统级监控 |
| 双向同步 | ⚠️ 单向为主 | ✅ 完全双向 |
| AI 工作流 | 依赖 AI「自觉」 | 完全解耦 |

### SyncThing 进阶：.stignore 配置

Obsidian vault 里不只有 Markdown 文件，还有 `.obsidian/` 文件夹（插件配置、主题缓存等）。

**.stignore 配置示例**：

```plaintext
.obsidian/
.DS_Store
*.tmp
```

**效果**：同步过来的就是干净的笔记，不带任何 Obsidian 的内部文件。

### 版本控制：比回收站更强的 Time Machine

SyncThing 自带多种版本控制模式，推荐 **Staggered File Versioning（交错版本控制）**：

| 时间范围 | 快照频率 |
|----------|----------|
| 最近 1 小时内 | 每 30 秒存一个版本 |
| 最近 1 天内 | 每小时存一个版本 |
| 超过 1 天 | 每天存一个版本 |

**适用场景**：工作流跑偏、整篇草稿被误删的恢复。

### 全平台支持

SyncThing 支持：

- Windows
- Mac
- Linux
- Android（官方 App）

**iOS**：不支持，需用其他方案（Remotely Save 或 Working Copy）

### SyncThing + Fast Note Sync 组合架构

两者各司其职，组合使用实现完整同步：

```
Mac ←→ 服务器：SyncThing（双向，文件系统级监控）
Mac → 手机：Fast Note Sync（单向，本地变化触发）
```

**架构图**：

```
服务器（OpenClaw）
     ↓ (写文件)
SyncThing 检测到变化
     ↓ (自动推送)
Mac (Obsidian)
     ↓ (Remotely Save)
手机 (Obsidian Mobile)
```

**职责说明**：

| 组件 | 职责 |
|------|------|
| SyncThing | 把服务器和 Mac 拉齐 |
| Fast Note Sync | 把 Mac 的变化推给手机 |

**为什么不能互换**：
- 缺了 SyncThing，Fast Note Sync 根本不知道服务器改了东西
- 缺了 Fast Note Sync，手机就收不到通知了

### SyncThing 管理界面

SyncThing 提供可视化界面，能看到所有设备、每个文件夹的同步状态：

- 文件没同步成功？上面写着原因
- 是网络不通，还是被 `.stignore` 拦了，一目了然

### 适用场景

iOS 用户需要完整 Git 功能。

### 安装

1. App Store 安装 Working Copy
2. 克隆 GitHub/GitCode 仓库

### 使用

1. 在 Working Copy 中编辑文件
2. Commit 和 Push
3. 配合 Obsidian Mobile 打开 Vault

### 工作流

```
Working Copy (编辑) → Git → Obsidian Mobile (查看)
                              ↓
                    Remotely Save (同步)
                              ↓
                        桌面端
```

## 移动端 Obsidian 设置

### 基础设置

1. 打开 Obsidian Mobile
2. 选择"打开本地保险库"
3. 选择 Vault 文件夹

### 同步注意事项

- Vault 路径必须与桌面端完全一致
- 建议使用相同的插件配置
- 注意 `.obsidian` 配置同步

### 插件移动端兼容性

| 插件 | 移动端支持 | 说明 |
|------|------------|------|
| Obsidian Git | ⚠️ 有限 | 推送可用，拉取有问题 |
| Remotely Save | ✅ 完全支持 | 推荐使用 |
| Templater | ✅ 支持 | 需配置模板路径 |
| Dataview | ✅ 支持 | 查询可能有延迟 |
| Calendar | ✅ 支持 | 移动端体验良好 |

## 同步冲突处理

### 原因

多端同时编辑同一文件。

### 处理方式

| 方式 | 说明 |
|------|------|
| 保留两者 | 创建 `文件名_冲突时间.md` |
| 手动合并 | 手动解决冲突 |
| 以桌面端为准 | 移动端覆盖 |

### 建议

1. 开启冲突通知
2. 定期手动检查冲突
3. 使用 Git 分支管理大版本

## 补充方案：易记 App + 微信语音输入法

对于碎片化灵感捕捉，推荐这套轻量级方案。

### 核心优势

| 优势 | 说明 |
|------|------|
| 极简 | 打开 App，输入内容，完成 |
| 快速 | 从解锁到完成记录，不超过 10 秒 |
| 自动 | 无需手动，内容自动同步到 Obsidian |

### 方案组合

```
易记 App（手机输入）→ 坚果云 WebDAV → Obsidian Vault
```

### 配置步骤

#### 第一步：配置坚果云 WebDAV

1. 登录坚果云客户端 → 设置 → 第三方应用管理
2. 点击"添加应用密码"，生成专用密码
3. 记录以下信息：
   - 服务器地址：`https://dav.jianguoyun.com/dav/`
   - 坚果云账号（邮箱）
   - 应用专用密码

#### 第二步：安装并配置易记 App

易记是一款极简的 Markdown 快速记录工具。

1. 安装易记 App
2. 进入设置，填入：
   - 服务器地址：`https://dav.jianguoyun.com/dav/`
   - 坚果云账号：你的邮箱
   - 第三方应用专用密码：刚才生成的密码
   - 保存目录：`inspiration`（与坚果云中创建的文件夹一致）
3. 点击"测试连接"验证配置

#### 第三步：配合微信语音输入法

强烈推荐搭配微信语音输入法：
- 中文识别准确率极高
- 支持语音转文字
- 骑车、散步、做家务时也能随手记录

### 使用流程

1. 打开易记，自动生成时间戳文件名（如 `20260326_150738`）
2. 输入你的想法（语音或文字）
3. 点击"保存到坚果云"

### 在 Obsidian 中加工

打开桌面端 Obsidian，刚才记录的 `.md` 文件已出现在 `inspiration` 文件夹：

- 为灵感添加标签
- 与已有笔记建立双向链接
- 基于灵感展开深入思考

### 与 Remotely Save 的对比

| 对比项 | 易记 + 坚果云 | Remotely Save |
|--------|---------------|---------------|
| 用途 | 快速捕捉灵感 | 完整 Vault 同步 |
| 体验 | 极简轻量 | 功能完整 |
| 内容 | 单向流动到 Vault | 双向同步 |
| 适合 | 碎片想法、口述笔记 | 完整编辑、同步 |

## 特殊场景：在手机端安装测试版同步助手

除了完整同步整个 Vault，有时你只想在手机端补充一个特定能力，例如把微信公众号文章同步进 Obsidian。这类场景通常需要安装测试版插件，而不是只依赖官方插件市场。

这时最稳的做法是：**先用 BRAT 安装测试版插件，再根据插件说明完成授权和同步。**

### 什么是 BRAT

BRAT（Beta Reviewers Auto-update Tester）是 Obsidian 社区常用的测试版插件安装器。

适合下面这些情况：

- 插件还没上正式市场
- 你需要先装 GitHub 上的预发布版本
- 手机端需要补充某个特殊同步能力

### 安装 BRAT 的步骤

![[mobile-helper-brat-flow.png|BRAT 安装流程示意]]

1. 打开 Obsidian Mobile，进入 `设置`
2. 打开 `Community plugins`
3. 首次使用时，点击 `Turn on community plugins`
4. 点击 `Browse` 进入插件市场
5. 搜索 `BRAT`
6. 安装并启用 BRAT
7. 进入 BRAT 的 `Options`

### 使用 BRAT 安装测试版同步助手

如果你的目标是同步微信公众号文章，可在 BRAT 中添加对应插件仓库地址。

以“笔记同步助手”为例：

1. 在 BRAT 设置中点击 `Add beta plugin`
2. 输入插件仓库地址  
   `https://github.com/notesynchelper/obsidian-notehelper`
3. 勾选“安装后自动启用”
4. 完成安装后，在社区插件列表确认插件已启用

### 同步助手的配置思路

这类插件通常都需要三类信息：

| 配置项 | 说明 |
|------|------|
| 插件仓库地址 | 用于 BRAT 拉取测试版 |
| 授权信息 / 密钥 | 用于访问服务端接口 |
| 执行命令 | 用于触发文章拉取或同步 |

以“笔记同步助手”为例，常见流程如下：

1. 打开插件设置页
2. 填入密钥
3. 打开命令面板
4. 执行同步命令
5. 等待文章写入 Vault

同步完成后，新增文章通常会直接出现在你的笔记列表中。

### 什么时候适合这类方案

- 你主要想同步“某一类内容”，而不是整个 Vault
- 你需要在手机端安装正式市场里还没有的插件
- 你愿意接受测试版插件偶尔不稳定的风险

### 和完整同步方案的区别

| 对比项 | 测试版同步助手 | Remotely Save / Obsidian Sync |
|------|------|------|
| 目标 | 补充单一能力 | 同步整个 Vault |
| 安装方式 | BRAT / GitHub | 正式插件 / 官方服务 |
| 稳定性 | 取决于插件维护情况 | 通常更稳定 |
| 适合人群 | 有明确特殊需求的用户 | 大多数用户 |

### 常见问题

**Q：安装时报 GitHub API 限流怎么办？**  
A：等待一段时间再试，或配置 GitHub Token 提高限额。

**Q：手机端能不能长期依赖测试版插件？**  
A：可以，但建议把它当“补充能力”，不要把核心同步完全押在测试版插件上。

**Q：如果插件同步失败怎么办？**  
A：先检查密钥、仓库地址和命令是否正确，再查看插件说明或 GitHub issue。

## 最佳实践

### 1. 文件命名规范

统一日期格式，便于排序：

```
2024-01-15-项目会议.md
YYYY-MM-DD-标题.md
```

### 2. 减少冲突

- 移动端主要用于查看和轻度编辑
- 大量编辑在桌面端完成
- 使用模板减少编辑时间

### 3. 定期同步

- 离开桌面前手动同步一次
- 移动端编辑后立即同步
- 睡前检查同步状态

## 常见问题

**Q：Remotely Save 显示连接失败？**

A：检查网络连接、API 密钥是否正确、存储服务是否可用。

**Q：SyncThing 同步慢？**

A：检查是否在同一个局域网内，调整同步间隔。

**Q：iOS 无法使用 SyncThing？**

A：iOS 不支持 SyncThing，建议使用 Remotely Save 或 Working Copy。
