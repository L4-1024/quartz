## 前言

![[core-concepts-guide.png|Obsidian 核心概念导览图]]

Obsidian 不仅仅是一款笔记软件，更是一套 **个人知识管理系统（PKM）** 的解决方案。它将你所有的笔记以纯文本 Markdown 格式存储在本地，让你真正掌握自己的数据。通过双向链接、图谱视图、插件生态等核心能力，Obsidian 能够帮助你建立知识之间的连接，发现隐藏的联系，构建属于你自己的「第二大脑」。

本篇将详细介绍 Obsidian 的核心概念，帮助你建立全局认知，为后续的深入学习打下坚实基础。

## 核心概念

### 1. 库（Vault）

Vault 是 Obsidian 管理笔记的根目录，可以是本地文件夹或同步盘。

```
my-vault/
├── .obsidian/          # 配置文件目录
├── 笔记文件夹/
│   ├── 笔记1.md
│   └── 笔记2.md
└── attachments/        # 附件文件夹
    └── 图片.png
```

**重要特性**：

- `.obsidian/` 目录包含所有配置、插件设置和缓存
- Vault 可以是本地文件夹，也可以是同步服务（如 iCloud、OneDrive、Dropbox）
- 支持创建多个 Vault，每个 Vault 完全独立

### 2. Markdown 文件

所有笔记以 `.md` 格式存储，支持的常用语法：

| 语法           | 说明             |
| ------------ | -------------- |
| `# 标题`       | 标题（1-6级）       |
| `**粗体**`     | 粗体             |
| `*斜体*`       | 斜体             |
| `[[链接]]`     | 内部链接到其他笔记      |
| `[[笔记名#标题]]` | 链接到特定笔记的特定标题   |
| `![[嵌入的笔记]]` | 将其他笔记的内容嵌入当前笔记 |
| `- 列表项`      | 无序列表           |
| `1. 有序列表`    | 有序列表           |
| `- [ ] 待办`   | 待办事项           |
| `` `代码` ``   | 行内代码           |
| ` ` 代码块` `   | 代码块            |
| `> 引用`       | 引用块            |

### 3. 双向链接（Backlinks）

双向链接是 Obsidian 最核心的特性，也是构建知识网络的基础。

![[wikilink-flow.png|内部链接、反向链接与搜索的关系示意]]

**创建链接**：在笔记中使用 `[[笔记名]]` 这种语法创建链接。

**反向链接**：当笔记 A 链接到笔记 B 时，笔记 B 会自动显示「反向链接」面板，展示所有链接到它的笔记

```markdown
# 笔记 A
这是对 `笔记 B` 的引用，主题是学习方法。

# 笔记 B 的反向链接面板
- 笔记 A 引用了你（关于学习方法）
```

**链接类型**：

| 语法             | 说明               |
| -------------- | ---------------- |
| `[[笔记]]`       | 链接到笔记，默认显示笔记名    |
| `[[笔记\|显示文本]]` | 链接到笔记，但显示自定义文本   |
| `[[笔记#标题]]`    | 链接到笔记的特定章节       |
| `![[笔记]]`      | 嵌入（Embed）笔记的全部内容 |

### 4. 图谱视图（Graph View）

图谱视图以可视化方式展示所有笔记及其链接关系，是 Obsidian 最具魅力的功能之一。

**核心价值**：

- 发现知识盲区：哪些笔记缺乏链接
- 揭示隐藏联系：看似无关的笔记之间可能存在潜在关联
- 理解知识结构：通过团簇（Cluster）发现主题聚类

**图谱类型**：

- **本地图谱**：查看单篇笔记的链接关系
- **全局图谱**：展示整个 Vault 的知识网络
- **标签图谱**：按标签组织的关系视图

### 5. 标签（Tags）

标签是跨文件夹组织内容的方式，比文件夹更灵活。

![[tag-system.png|标签系统的组织方式示意]]

**基础语法**：`#标签名`

**嵌套标签**：`#工作/项目A`、`#学习/技术/编程`

**标签面板**：侧边栏显示所有标签的统计和层级

**最佳实践**：

- 标签数量不宜过多（建议不超过 50 个核心标签）
- 使用统一命名规则，如 `#领域/主题/子主题`
- 避免用标签替代文件夹，两者是互补关系

### 6. 属性（Properties）

属性是笔记的「身份证」，位于笔记顶部的 YAML 前置区域，为笔记添加结构化元数据。

```yaml
---
title: 读书笔记
author: 作者名
rating: 5
status: 已读
created: 2024-01-15
tags:
  - 书籍
  - 推荐
type: literature
---

# 我的读书笔记
```

**核心属性类型**：

| 属性        | 说明              |
| --------- | --------------- |
| `title`   | 笔记标题            |
| `created` | 创建日期            |
| `tags`    | 标签列表            |
| `aliases` | 别名/同义词          |
| `status`  | 状态（如：想法/进行中/完成） |

**属性用途**：

- 通过 Dataview 插件进行动态查询
- 数据库插件可视化展示
- 搜索和筛选的精确条件

### 7. 搜索系统

Obsidian 内置强大的搜索功能：

![[search-syntax-map.png|搜索入口、语法与组合检索示意]]

| 快捷键                | 功能                    |
| ------------------ | --------------------- |
| `Ctrl + O`         | 快速切换器（Quick Switcher） |
| `Ctrl + F`         | 当前文件搜索                |
| `Ctrl + Shift + F` | 全局搜索（搜索所有文件）          |

**搜索语法**：

- `word` - 包含 word 的内容
- `"exact phrase"` - 精确匹配短语
- `tag:#工作` - 搜索特定标签
- `path:文件夹` - 搜索特定路径
- `task:- [ ]` - 搜索未完成的任务

## 插件系统

Obsidian 的强大之处在于其丰富的插件生态，分为**核心插件**和**社区插件**。

### 核心插件（内置）

| 插件              | 功能            |
| --------------- | ------------- |
| 模板（Templates）   | 快速插入预定义文本片段   |
| 日记（Daily Notes） | 创建每日记录        |
| 日历（Calendar）    | 可视化日记和任务      |
| 搜索（Search）      | 全局搜索          |
| 反向链接（Backlinks） | 查看引用当前笔记的所有链接 |
| 标签面板（Tag Pane）  | 显示所有标签        |

### 热门社区插件

| 插件               | 功能              |
| ---------------- | --------------- |
| **Dataview**     | 类数据库查询，支持动态数据展示 |
| **Templater**    | 高级模板系统，支持脚本和变量  |
| **Obsidian Git** | 自动 Git 版本控制     |
| **Linter**       | 格式化整理 Markdown  |
| **Claudian**     | AI 助手集成         |
| **Reminder**     | 任务提醒            |
| **Excalidraw**   | 绘图和白板功能         |
| **Database**     | 表格视图管理笔记        |

### 插件安装建议

**核心插件**：按需启用，太多会影响性能

**社区插件**：

1. 先明确需求，避免安装过多「可能用到」的插件
2. 优先选择活跃维护的插件
3. 安装后逐步配置，了解每个插件的用法

## 模板系统

模板是快速创建标准笔记的利器，是建立工作流自动化的基础。

### 基础模板变量

| 变量              | 说明               |           |
| --------------- | ---------------- | --------- |
| `{{date}}`      | 当前日期（2024-01-15） |           |
| `{{time}}`      | 当前时间             |           |
| `{{title}}`     | 当前笔记标题           |           |
| `{{filename}}`  | 当前文件名            |           |
| `{{cursor}}`    | 模板插入后光标位置        |           |
| \`{{surround:前缀 | 后缀}}\`           | 在选中文本外围包裹 |

### 模板类型示例

**日记模板**：

```markdown
# {{date:YYYY-MM-DD}} 日记

## 今日完成
-

## 明日计划
-

## 思考
-
```

**读书笔记模板**：

```markdown
---
title: {{title}}
author: 
date: {{date}}
rating: 
status: 未读
tags:
  - 读书
---

# {{title}}

## 主要内容

## 关键要点

## 个人思考

## 行动清单

- [ ]
```

### 进阶：Templater 插件

对于高级用户，Templater 插件支持：

- JavaScript 脚本控制
- 条件逻辑判断
- 动态内容生成
- 与外部 API 交互

## Dataview 查询

Dataview 是 Obsidian 最强大的插件之一，它将笔记转化为可查询的数据库。

### 基本语法

```dataview
TABLE title, created, tags
FROM ""
WHERE type = "clipps"
SORT created DESC
```

### 查询类型

| 类型      | 说明     |
| ------- | ------ |
| `TABLE` | 表格形式展示 |
| `LIST`  | 列表形式展示 |
| `TASK`  | 仅显示任务  |

### 典型应用场景

1. **项目任务总览**：汇总所有项目相关任务
2. **读书清单**：按状态筛选待读/已读书籍
3. **每日回顾**：展示今日创建的笔记
4. **未完成事项**：集中展示所有待办

## 同步与备份

数据安全是知识管理的基石。Obsidian 提供多种同步方案。

### 官方同步

- **Obsidian Sync**：官方云同步服务
- 支持端到端加密
- 跨设备无缝同步
- 按年订阅

### 本地同步方案

| 方案                  | 说明                |
| ------------------- | ----------------- |
| **Obsidian Git**    | 插件形式，自动提交到 Git 仓库 |
| **iCloud/OneDrive** | 云盘同步，适合个人使用       |
| **Git + 同步盘组合**     | 多设备用 Git，备份用同步盘   |

### 推荐的本地同步方案

```
设备 A（PC）→ Git 推送 → GitHub/Gitee → Git 拉取 → 设备 B（Mac）
                 ↑
            定期自动提交
```

**Obsidian Git 配置要点**：

- 设置自动提交间隔（如每 30 分钟）
- 配置忽略文件（.obsidian/workspace）
- 远程仓库使用私有仓库

## 工作流架构

一个完整的 Obsidian 工作流通常包含以下环节：

```
采集 → 整理 → 连接 → 输出 → 同步
```

### 采集阶段

**快速记录**：

- 手机端使用微信配合 Share 功能到 `Obsidian助手`
- QuickAdd 插件快速创建笔记
- 日记插件记录每日灵感

### 整理阶段

**元数据完善**：

- 添加属性（title, tags, status, dates）
- 使用模板标准化结构
- Linter 插件自动格式化

### 连接阶段

**构建知识网络**：

- 养成双向链接习惯
- 定期使用图谱视图发现断点
- 通过 Dataview 查询验证知识完整性

### 输出阶段

**知识变现**：

- 撰写文章和博客
- 输出项目文档
- 制作分享用的 Canvas

### 同步阶段

**多端一致**：

- 配置 Obsidian Git 自动同步
- 重要内容多重备份
- 定期检查同步状态

## 个人知识管理（PKM）

Obsidian 是 **Personal Knowledge Management（个人知识管理）** 的绝佳工具载体。

### 核心理念

| 理念        | 说明                 |
| --------- | ------------------ |
| **原子化**   | 每条笔记只记录一个独立想法      |
| **链接优先**  | 优先使用内部链接而非过深的文件夹分类 |
| **渐进式完善** | 先记录，再迭代优化          |
| **定期回顾**  | 通过反链发现知识断点         |

### Zettelkasten 方法

这是一种经典的笔记方法论，与 Obsidian 完美契合：

1. **fleeting notes**：快速记录闪念笔记
2. **literature notes**：记录书籍/文章的摘要和想法
3. **permanent notes**：将知识转化为原子化的永久笔记
4. **索引笔记**：建立笔记之间的链接索引

### 知识管理循环

```
阅读/学习 → 做笔记 → 建立链接 → 定期回顾 → 产出成果 → 迭代优化
```

## Obsidian 的独特优势

### vs 传统笔记软件

| 特性   | 传统笔记   | Obsidian  |
| ---- | ------ | --------- |
| 数据存储 | 云端/数据库 | 本地 .md 文件 |
| 链接能力 | 弱或无    | 强大双向链接    |
| 可迁移性 | 差      | 完全可迁移     |
| 锁定风险 | 高      | 无         |
| 离线可用 | 通常需要网络 | 完全离线      |

### vs 其他双链笔记

| 特性       | Notion | Obsidian |
| -------- | ------ | -------- |
| 离线可用     | ❌      | ✅        |
| 数据所有权    | ❌      | ✅        |
| 本地文件     | ❌      | ✅        |
| Git 版本控制 | ❌      | ✅        |
| 可自定义程度   | 中等     | 极高       |
| 学习曲线     | 平缓     | 较陡       |
